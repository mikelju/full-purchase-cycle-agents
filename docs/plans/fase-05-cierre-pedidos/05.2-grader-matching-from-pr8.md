# Deviation 05.2 - Email grader matching from PR 8

Status: approved
Phase: `spec.md` and `plan.md` in this folder (increment 25 done, review round 1 fixed)

## What happened
PR 8 (branch `cambio-003-email-grader-matching`, commit `c6b3d65`, base `f1a1e4f`) fixes the email grader `src/purchase_cycle/evaluation/email_eval.py` and overlaps increment 25 of this phase.
Checked against the current code on 2026-10-09, it adds two things that increment 25 does not have:

1. SKU-only credit order: `field_sku` is given in the order of the expected lines, so with a repeated SKU the SKU credit can go to a line whose quantity does not match while the line that matched exactly gets none.
   Example: expected A x5 and A x3, produced A x3 gives `field_sku` to the A x5 line and `line_recall` to the A x3 line.
2. Out-of-catalog text: an expected out-of-catalog line passes on quantity and source only, so a produced unknown line with another product ("Hospital beds" for "Syringes 60 ml") still counts as detected.
   PR 8 checks the requested text with a substring test and a greedy pairing.

The review of PR 8 found defects in its text check:
- Substring, not whole words: the expected "gel" matches a produced "Angel wings".
- Greedy pairing: expected "FFP1 masks" and "FFP1 masks, box" with the produced lines in reverse order score 1 of 2.
- Copying a whole table into `source_text` matches every expected line whose text it contains.
- An out-of-catalog mismatch on text alone leaves the failure reason without an explanation.

What C20 says now: an unknown line passes only with the expected quantity and source; a catalog line passes only with the expected SKU, quantity and source; a produced line counts for at most one expected line.

## New rule
- Catalog lines: `line_recall` stays over (SKU, quantity, source); `field_sku` and `field_quantity` are given to exact (SKU, quantity) matches first, and SKU-only credit goes to the produced lines left over.
- Out-of-catalog lines: a produced unknown line matches an expected one only if source and quantity match and the expected requested text appears in the produced `source_text` as whole words (casefold, whitespace collapsed, word boundaries).
- Candidate rule per produced line: take the expected out-of-catalog texts found in its citation and drop any that is a sub-phrase of another one in that set; if more than one distinct text remains, the line matches nothing.
  So a citation that copies a whole table earns nothing, and "FFP1 masks, box" matches the expected "FFP1 masks, box", not "FFP1 masks".
- Pairing is an optimal one-to-one maximum matching (augmenting paths), not greedy; out-of-catalog detection holds when every expected and every produced unknown line is paired.
- The failure reason names an out-of-catalog text mismatch.

Amended C20 (new words in the second clause): an unknown line passes only with the expected quantity and source and with its requested text in the produced citation under the candidate rule above (deviation 05.2).
The C20 stop rule applies to the re-score: if any figure drops, the code is committed but no baseline or threshold changes and the drop goes to the owner.

## Decision
The owner decided on 2026-10-09 via Lavish: option C for PR 8 (what PR 8 adds comes into phase 05 and the owner closes the PR) and option A for the text check (added to C20 as this deviation, with the review findings fixed first).
The spec amends C20, the plan gains batch A1 (increment 29), and the master plan is unchanged in scope.
